## Why Build Your Own?

Most teams start with a UI library like MUI or Chakra. They work fine until you need deep customization. At Agilae, we needed pixel-perfect control over our insurance platform's UI while maintaining consistency across 40+ screens.

## Token-Based Architecture

The foundation is a token system. Not just colors — spacing, radius, shadows, transitions. Everything maps to CSS custom properties:

```css
@theme inline {
  --color-secondary-container: #00eefc;
  --spacing-gutter: 24px;
  --radius-2xl: 1rem;
}
```

Tokens live in `theme/index.ts` as a single source of truth. Components consume them through Tailwind classes or direct CSS variable references.

## Component Composition

We follow the Radix UI pattern: unstyled primitives with composable slots. Our `Button` component accepts `variant`, `size`, and `asChild` props. The `GlassPanel` handles backdrop blur, border glow, and hover states.

The key insight: separate visual treatment from behavior. A card is just a container with glass morphism. The content inside decides what it does.

## Dark/Light Mode

Theme switching isn't a toggle — it's a system. CSS variables swap at the `[data-theme]` level. Framer Motion handles transitions. The anti-flash script in `<head>` prevents white flicker on load.

## What I'd Do Differently

1. Start with CSS layers earlier
2. Use `@property` for animated custom properties
3. Document tokens in Storybook from day one

The system now powers 3 production apps with zero style conflicts.
